# План развития агента (обновлён 12.11.2026)

Принципы: ядро неизменно; всё новое сначала в лаборатории и песочнице; в рабочий код только после «да» владельца; честность по Кодексу; экономия лимитов; никаких обходов запретов платформ.

## Уже сделано
Bluesky, Moltbook, Mastodon · человеческий язык · лёгкий проверяющий · слоистая память (люди, факты, векторы, связи) · исследование сети · дневной план и вечерняя рефлексия · песочница инструментов и проекты модулей · чат с владельцем в Telegram (черновики по «да», тихий режим, утренний дайджест) · длинные запуски по 5,5 часов · бюджет лимитов и приоритеты · лаборатория в этом репозитории · журнал действий для аудита.

## Ближайшее (после проверки первого длинного запуска)
1. Проверить: цикл идёт ~5,5 ч, чат отвечает, дайджест в 09:00, папки `lab/` и память пишутся, расход лимитов в норме. Исправить найденное.
2. Разбор репозитория сторонним ревью (ChatGPT): собрать замечания в `lab/reports/`, отобрать по пунктам, чинить по одному.
3. Mastodon: перегенерировать токен (был частично засвечен), проверить правила сервера, потом решить про публичную видимость.
4. SambaNova: добавить секрет, посмотреть реальные квоты, подогнать `BUDGET` в коде.

## Следующий этап: узкие воркеры
Разделить агента по ролям, по одной за раз, у каждой свой workflow и свой файл состояния:
- исследователь (чтение сети, заметки)
- публикатор (посты и ответы)
- хранитель памяти (факты, рефлексия, чистка)
- мастер инструментов (песочница, лаборатория)
- собеседник (ответы людям)
Цель: меньше токенов на задачу, сбой одной роли не валит остальных.

## Лаборатория
- Путь: lab → отчёт → «да» владельца → репозиторий агента.
- Позже: изолированные тесты в отдельном репозитории без секретов (запуск через Actions API).
- Дальше: адаптеры для новых сетей (только открытый API, без скрейпинга), расширения архитектуры как проекты.

## Качество и доверие
- Проверка фактов по первоисточникам, цитаты-доказательства в исследованиях.
- Метрики: ответы людям, повторные собеседники, отказы проверяющего, расход лимитов. Публиковать и нулевые результаты.
- Идентичность: публичная страница и A2A-карточка поддерживаются в актуальном виде.
- Правила контакта: отвечаем тем, кто пишет сам; никаких массовых рассылок и давления; запрос «хватит» заканчивает контакт.

## Параллельно: тесты Кодекса (отдельный репозиторий)
Судья заканчивает. Затем: сводная таблица, повторная оценка второй моделью на выборке, ручная проверка 10%, README и сайт, отклонения от пререгистрации, повторная оценка ошибочных строк, недостающие ответы Cohere 4, модели OpenRouter.
